# 浏览器导入（浏览器扩展一键入库）

在 Chrome / Edge 里装上随附的浏览器扩展后，打开论文网页或 PDF，点一下浏览器工具栏的扩展图标（或右键菜单「导入此页面/链接」），文献就进入工作台文献库的「待整理」分区——等价于 Zotero Connector 的体验。

**隐私边界**：所有流量只发往本机 `127.0.0.1`，无任何上传；PDF 经浏览器直接落到本地库。

## 架构

```
浏览器扩展 (MV3)                        工作台 (Electron 主进程)
┌─────────────────────────┐   POST     ┌──────────────────────────────┐
│ 1. 读页面 citation 元标签 │ ────────► │ 127.0.0.1:31415 /api/import  │
│ 2. 抓 PDF（带登录态）     │  JSON     │  令牌/来源校验 → 校验载荷      │
│ 3. 付费墙兜底：下载落盘   │ ◄──────── │  → repo.importDocuments      │
└─────────────────────────┘   结果     │  → 文献库/待整理 + toast      │
                                       └──────────────────────────────┘
```

- 服务端：`src/main/server.ts`（`/api/import`、`/api/import/ping`），导入核心 `src/main/browser-import.ts`
- 扩展：`extension/`（manifest + background + options），打包时经 electron-builder `extraResources` 进 `resources/extension`

## 安装扩展（Chrome / Edge 通用）

1. 工作台 → 文献库 → **「浏览器导入」**按钮 → **「打开扩展文件夹」**（打包版在 `resources/extension`，开发模式在仓库 `extension/` 目录）。
2. 浏览器地址栏进入 `chrome://extensions`（Edge 为 `edge://extensions`）。
3. 打开右上角「开发者模式」→「加载已解压的扩展程序」→ 选择上一步的 extension 文件夹。
4. 回到工作台弹窗 **「复制令牌」**，打开扩展的「选项」页粘贴（服务地址默认 `http://127.0.0.1:31415`，一般不用改）→「测试连接」显示成功即可。

端口与令牌也落在 `<userData>/settings.json`（`prefs.importPort` / `prefs.importToken`）；令牌首次启动自动生成。

## 导入行为

| 场景 | 行为 |
| --- | --- |
| arXiv 摘要页 / 出版商文章页 | 读 `citation_*` / DC 元标签（标题、作者、DOI、期刊、年份、摘要、PDF 直链），抓 PDF 入库 |
| 直接打开的 PDF（含 Chrome 内置查看器） | 按当前 URL 抓 PDF；arXiv 链接自动补 arXiv ID |
| 付费墙 / 浏览器内抓不到 | 扩展自动改走浏览器下载器落盘，把本机路径交给工作台复制入库 |
| 普通网页（无 PDF） | 只建书目条目（无文件），原文之后可拖入 |

入库统一走既有导入管线（`repo.importDocuments` → `updateDocument` → `updateEntryMeta`）：

- **查重**：DOI → arXiv ID → 文件 sha256，任一命中即报「已在库中」，不重复建条目。
- **元数据策略**：页面带了真实书目（作者/DOI/arXiv/年份+期刊）→ 条目置 ok；只有标题 → 保持「待补全」并即时挂识别队列（Crossref/arXiv 回填，同 Zotero/每日论文策略）。
- **来源留痕**：`note` 字段记 `浏览器导入：<来源页 URL>`。

## 传输协议（本地 HTTP API）

### `GET /api/import/ping`

需令牌。响应 `{ ok: true, name, app, electron, node }`，供扩展「测试连接」与服务发现。

### `POST /api/import`

需令牌 + `Content-Type: application/json`。请求体：

```jsonc
{
  "title": "论文明细（可缺省，回退文件名）",
  "authors": ["张三", "Li Si"],      // 数组或逗号分隔字符串
  "year": 2024,                       // 1400–2100 整数，非法忽略
  "venue": "arXiv", "doi": "10.xxxx", "arxivId": "2401.12345",
  "abstract": "…", "tags": ["弱辨识"],
  "sourceUrl": "https://arxiv.org/abs/2401.12345",
  "pdfBase64": "JVBERi0xLj…"          // 与 localPath 二选一；都没有则建无文件条目
  // "localPath": "C:\\Users\\..\\paper.pdf"   // 扩展下载兜底：复制入库
}
```

响应 `{ ok, documentId?, title?, duplicate?, needsReview?, error? }`；`needsReview=true` 表示条目保持待补全（工作台会即时挂识别队列）。

## 安全模型

- 只绑定 `127.0.0.1`，默认端口 31415（被占用依次试 31416/31417，再回落随机端口）；实际端口写回设置供 UI 展示。
- **令牌必需**（`X-MWB-Token` 头，sha256 后定长比较防时序侧信道）；扩展选项页粘贴配对。
- **来源校验**：带 `Origin` 的请求只放行 `chrome-extension://` / `moz-extension://`；普通网页即便拿到令牌也会被 403（防恶意页面塞内容进库）。
- 请求体必须 `application/json`（表单型跨站请求被 415 拦截）+ 大小上限 180 MB。
- PDF 载荷服务端二次校验 `%PDF-` 魔数与大小上限（128 MB）；`localPath` 模式同样校验后才复制。

## 已知限制

- Firefox 未适配（清单是 Chromium MV3；需小改 `browser_specific_settings` 与下载 API 差异）。
- 工作台未运行时扩展会明确报「连不上工作台」，不会自动拉起应用（可后续用 `mathworkbench://` 深链补）。
- Chrome 内置 PDF 查看器里拿不到页面元标签，只有文件名标题——建议从文章页点导入，元数据更全。
