# 存储格式 v2：纯文件夹 + 内存索引

版本：2026-10-07。对应 ADR-7（文件即真相）。本文件是新存储层的**唯一格式规范**；主进程扫描/写入、迁移脚本、测试夹具都以它为准。

## 0. 设计铁律

1. **身份不靠路径**：条目、笔记、锚点、照片的身份是文件内部的 UUID；移动/重命名分区或条目文件夹不断链。
2. **程序生成的文件可丢弃**：只允许出现在条目内 `derived/` 和库根 `.cache/`；删掉后程序必须能从原件 + 元数据完整重建。
3. **原子写**：所有程序写入走「同目录临时文件 → rename 覆盖」，任何时刻断电/同步都不产生半成品。
4. **原件永不修改**：PDF/HTML/图片原件导入后只读（与 v1 一致）。
5. **坏文件先备份再回退**：JSON 文件解析失败时，先把坏文件改名为 `<名>.broken`，再按缺省值处理。
   这些文件都是**整份替换式**写入，若只当空内容，用户下一次操作就会把它覆盖掉、原内容永久消失。
   覆盖范围：entry.json、anchors.json、墨迹（`ink/…/pN.json`）、精读.json、settings.json、足迹.json、分区.json
   （实现见 `fsutil.ts` 的 `readJsonSafeSync` / `readJsonSafeAsync`；settings/足迹/分区 早先各自实现过一遍）。
6. **笔记 .md 是上述备份策略的例外（有意为之）**：笔记文件本身就是用户文档，且「不在索引里」就意味着
   应用不可能写回它（保存必须先取到索引节点）——没有「被当成空内容覆盖」的风险。因此 .md 解析失败时
   **不搬移、不改名、不改写**（搬移会让用户在原位置找不到自己的文件），只在扫描器的 malformed 清单里
   记下相对路径，由文献库横幅提示（见 §9 库诊断）。修复文件内容后，下一次重扫即恢复。

## 1. 库根目录布局

库根 = `<userData>/library/`（用户机器上经目录联接落在 iCloud Drive，本方案不改变位置）。

```
library/
├── 文献库/                     ← 文献条目区
│   ├── 待整理/                 ← 默认分区（导入未归类/识别失败的落点）
│   └── <分区名>/               ← 用户分区，一级扁平（细分用 tags）
│       └── <条目名>/           ← 一篇文献一个文件夹，人读名（可重命名，不影响身份）
│           ├── entry.json
│           ├── <论文名>.pdf    ← 原件（可多份：同名论文的不同版本/补充 PDF/HTML）
│           ├── anchors.json
│           ├── 精读.json
│           ├── ink/<sha8>/p<page>.json
│           └── derived/       ← fulltext.txt 等，可删
├── 笔记/<slug>-<id8>.md        ← Wiki 页，一页一文件
│   └── 附件/<sha256>.<ext>     ← 笔记插图（内容寻址，全局去重）
├── 收件箱/<名>.jpg + <名>.json ← 手写照片 + 侧车元数据（§5.0）
│   └── 速记/<时间戳>-<id8>.md  ← 纯文本速记：front-matter + 正文（§5.1）
├── 学习区.json
├── papers.json
├── 足迹.json                   ← 学习足迹活动记录（§4.2；从启用日起）
├── 分区.json                   ← 分区颜色标签（§4.3；纯显示属性）
└── .cache/                    ← 索引缓存、图片派生图；可整目录删除
```

扫描器（FolderStore）对未知文件/未知字段**宽容**：忽略不报错；对缺失的必填字段按缺省补齐（**只在内存里补齐，不回写**——扫描是纯读，只有用户编辑才落盘）。目录/文件名仅用 NTFS/APFS 通用合法字符（`\ / : * ? " < > |` 与控制字符禁用），长度上限 120 字符。

## 2. entry.json（文献条目元数据 = 唯一真相）

```jsonc
{
  "schema": 2,                       // 格式版本，固定 2
  "id": "<uuid>",                    // 条目身份，永不变
  "docType": "paper",                // book | paper | other
  "title": "论文标题",
  "authors": ["First Last", "…"],   // 结构化作者列表（新）；迁移时从旧 authors 字符串拆分
  "year": 2024,                      // 出版年，number | null
  "venue": "期刊/会议名",             // string | null
  "doi": "10.xxxx/xxxx",             // string | null（不带 https://doi.org/ 前缀）
  "arxivId": "2401.12345",           // 不带版本号；string | null
  "abstract": "…",                   // string | null
  "tags": ["弱辨识", "Heston"],      // 自由标签
  "spaceId": "<uuid> | null",        // 学习区归属（双轨制：分区管归类，学习区管任务）
  "status": "ok",                    // ok | needs-review（识别失败的待整理标记）
  "note": "…",                       // 原 documents.note 自由备注
  "files": [                         // 顺序即版本顺序；sha256 即传输层 versionId/assetId
    {
      "sha256": "<hex64>",
      "name": "Attention Is All You Need-2017.pdf",
      "mediaType": "application/pdf",
      "byteSize": 1234567,
      "pageCount": 15,                // 可空；打开时由阅读器回填
      "fingerprint": null,            // 可空
      "importedAt": "<iso>"
    }
  ],
  "readingState": { "pageIndex": 3, "scale": 1.2, "rotation": 0 } | null,
  "createdAt": "<iso>",
  "updatedAt": "<iso>"
}
```

- **分区** = 条目文件夹的父目录名，不入 entry.json（以文件系统为准；程序移动分区 = 重命名目录）。
- **分区管理语义**（UI 文献库左栏）：新建 = 建目录；重命名 = 目录改名（条目随目录走，不断链）；删除 = 条目全部移回「待整理」后移除空目录。「待整理」不可改名/删除。分区清单由目录列举 + 条目计数聚合（空分区也可见）。分区行右键（或行内「⋯」）打开菜单：颜色标签（§4.3）、只看这个分区、重命名、在文件夹中显示、新建、删除。
- **收藏标记**：entry.json `starred: true`（仅收藏时写入键，不收藏不落键）。
- **条目文件夹名** = 净化后的标题（`sanitizeName(meta.title)`）；重名时追加 `-<id8>`。文件夹改名仅是展示，随时允许，**不参与解析**（身份是 entry.json 里的 UUID）。
- 同一 `sha256` 全库唯一：重复导入返回已有条目（保持 v1 语义）。

## 3. anchors.json（条目内锚点列表）

```jsonc
[
  {
    "id": "<uuid>",
    "fileSha": "<hex64>",            // 绑定的文件（= 传输层 documentVersionId）
    "pageIndex": 0,                  // 0 基物理页
    "pageLabel": null,               // 展示用打印页码
    "rects": [[x0, y0, x1, y1]],     // PDF 用户空间（coords.ts 契约不变）；空数组 = 页级锚点
    "quote": "选中文本",
    "createdAt": "<iso>"
  }
]
```

笔记的来源引用锚点时只存 `{kind:'anchor', anchorId}`，解析经内存索引（锚点 → 条目）。删除条目 = 整个文件夹移除。

> **现状（与设计意图有差距）**：来源解析不到的项目前是**静默跳过**——`getNoteFull` 找不到锚点/照片/条目时不产出任何标记，所以笔记的「来源与关联」会无声减少，用户看不出发生了什么。设计意图是标为 `missing` 并在 UI 显示「来源已删除」，尚未实现。

## 4. 笔记 markdown（笔记/<slug>-<id8>.md）

YAML front-matter + 正文；正文即 `bodyMd`（`[[双链]]` 语法不变）。

```markdown
---
schema: 2
id: <uuid>
noteType: concept        # concept|theorem|proof|example|counterexample|problem|note
title: 弱辨识性
aliases: [weak identifiability]
verifiedStatus: unchecked
spaceId: null
revision: 3
sources:                 # 原 note_sources + note_document_sources
  - kind: anchor         # anchor | capture | document
    id: <uuid>
    documentId: <uuid>   # anchor 来源附带的条目 id，冗余存储加速解析
createdAt: <iso>
updatedAt: <iso>
---
正文 markdown…
```

- 文件名 = `slug(标题)-<id前8>`；改名（标题变化）时重命名文件并**把旧标题并入 aliases**（保持 v1 wiki 引用不断的语义）。文件名不参与解析，仅防碰撞。
- **修订历史不存储**（v1 note_revisions 有意不迁移）；`revision` 仅作计数器防覆盖竞争。
- `counted`（可选，学习足迹内部标记）：已计过「新建」（首次非空正文）。仅置 true 时写入；防止清空正文再写被重复计为新建。

### 4.0 知识块的显示约定（不改变正文存储格式）

- 二级标题 `##` 划分知识块，三级标题 `###` 划分例子、推导、自测、参考解释等展开区。普通 Markdown 与公式仍是唯一内容来源；不生成第二份知识正文。
- 标题下可写 `<!-- block:potential -->` 保留稳定块 ID（ASCII 字母、数字、下划线、短横线）；未标注时由标题生成，重复 ID 自动区分。注释不显示在阅读界面。
- 地图是标题组织的导航，不表示自动推断的定理关系。跨笔记关系继续使用 `[[标题或别名]]`。
- **自评状态存在笔记 front-matter 的 `learning` 字段**（2026-10-09，WP-8 起；此前存机器本地 `settings.json` 偏好，双机工作流下换机即丢）：
  ```yaml
  learning:
    activeId: potential            # 当前块（「继续上次学习」）
    records:
      potential: { status: understood, fingerprint: 1a2b3c }
  ```
  指纹 = 知识块内容哈希（`contentFingerprint(标题+正文)`）：内容变化后旧标记自动失效；`status` 只允许 `understood` / `question`；无标记时**不落键**（往返无损）。
- 自评**不算内容编辑**：`saveNote` 携带 `learning` 时不改 `revision`、不刷新 `updatedAt`、不记学习足迹；它随同一条保存管线落盘（冲突保护与关窗冲刷自动生效），因此跨设备随库同步。
- 旧数据迁移：笔记无 `learning` 且存在旧 pref 键时，学习视图首次打开会把记录搬进笔记文件一次（不删旧键，键随后不再被读取）。

### 4.1 笔记插图（笔记/附件/）

- 文件名 = `<sha256>.<ext>`（内容寻址，全局去重，重复插入幂等）；`<ext>` 由文件头嗅探确定，嗅探不出退回扩展名（HEIC 变体兜底）。
- 正文引用语法：`![](asset:<sha256>)`，渲染时展开为 `/api/asset/<sha256>?variant=display`（png/jpg 原样返回，heic/tiff 自动转 jpg；引用里不含端口，跨会话/跨机器有效）。
- 附件是**原件级数据**（用户创作内容），不属于可丢弃缓存；扫描器按文件名建索引（同 entry 文件策略，不做全量哈希）。删除笔记不删除附件（孤儿附件无副作用，未来可加清理入口）。

### 4.2 足迹.json（学习足迹活动记录）

```jsonc
{
  "schema": 3,
  "startedAt": "<iso>",              // 启用日：足迹只承诺记录此之后的本机活动，不迁移、不补造历史
  "events": [
    {
      "id": "<uuid>",
      "kind": "note-created",        // note-created | note-updated | anchor-added | reader-session | ink-saved | block-reviewed
      "at": "<iso>",                 // 绝对时间
      "date": "2026-10-08",          // 事件发生时的本地日期（跨时区后历史归属不漂移）
      "noteId": "<uuid>",            // 稳定 ID；删除后展示「已删除」（附 title 快照）
      "documentId": "<uuid>",        // anchor-added / reader-session / ink-saved 附带
      "title": "事件时标题快照",        // 存活对象以索引实时标题为准
      "spaceId": "<uuid>|null",      // 事件发生时的学习区快照；移动笔记不改写过去足迹
      "groupId": "<uuid>",           // 摘录+伴随建笔记合并叙述用（可选）
      "pages": 4,                    // reader-session：本次会话翻到的去重页数（可选）
      "seconds": 600,                // reader-session：会话时长（秒，可选）
      "strokes": 12,                 // ink-saved：笔画数（可选）
      "pageIndex": 3,                // ink-saved：页码（可选）
      "status": "question"           // block-reviewed：understood | question（可选）
    }
  ]
}
```

- **只在 Repo 写路径产生事件**（saveNote 首次非空正文/正文变化、createAnchor、createAnchorWithNote、saveInk、saveNote 里自评状态的变化）：外部同步、索引重建、fs.watch 都不会把非本机行为计成学习活动。
- **阅读按会话聚合**：渲染层在导航冲刷/卸载时把「这段时间翻了哪些页（页面挂载即计入去重页数）」汇总成一条 `reader-session` 上报，不每页写盘；**<10 秒且没翻页的会话不计**（打开又关掉不算学习）。
- 口径：空白占位不计；零变化重复合存不计（`updatedAt` 同样只在真实变化时刷新）；改名/移动/分类/来源管理不计；保存失败无事件；自评只在状态**发生变化**的块上计（同状态重复保存不重复计）。
- 原子写 + 单写者；写入失败事件保留内存、标记 unhealthy（面板提示「活动记录暂不可用」），下次写入自动重试，不影响正文保存。
- **schema 2 → 3 宽容升级**：旧文件原样读入、旧事件不丢，下一次写入整体升级为 3；未知 kind 的事件保留并写回（前向兼容）。

### 4.3 分区.json（分区颜色标签）

```jsonc
{
  "schema": 1,
  "colors": { "正则化理论": "blue", "高维反问题": "purple" }   // 分区名 → 颜色 id；只存已设色的分区
}
```

- 颜色 id 白名单：`red | orange | yellow | green | blue | purple | gray`（`shared/types.ts` 的 `SECTION_COLORS`）。取值是语义色，色值与主题在渲染层（`styles.css` 的 `--section-color-*`）——换主题/调色不需要迁移数据。
- **为什么是库根的单文件而不是分区目录里的隐藏文件**：分区目录里出现非「条目文件夹」的任何东西都会与外部同步工具/扫描语义纠缠；库根单文件一次读取即可回填整个分区栏，且不参与条目扫描（扫描器对未知文件宽容）。
- 键 = 分区目录名。重命名分区时随目录迁移（`sectionRename`），删除分区时清理（`sectionDelete`）；外部（Finder/iCloud）直接改名会让键变成孤儿键——不显示、不报错，同名分区再次出现时会复用该颜色（有界行为，不做自动清理）。
- 非白名单值（手改文件/未来版本降级）读取时按「未设色」处理且不写回；整个文件损坏时备份为 `分区.json.broken` 并重建空表，不抛出。
- 分区颜色是**显示属性**：不影响归类、检索（按 `分区:` 检索的是目录名）、身份与同步。原子写 + 串行写链，失败只记日志（不阻断设色操作）。

### 4.4 保存冲突保护（磁盘指纹乐观并发，2026-10-09）

- 渲染层加载笔记时拿到 `baseHash`（磁盘原文的 sha1），每次成功保存后用返回值刷新；
- 保存时主进程在写盘前**对磁盘现读现算同一指纹**：与 `baseHash` 不一致 → **拒绝写入**，
  返回磁盘当前版本（`NoteSaveResponse.disk`，含无法解析时的原始文本兜底）；
- 界面三个出口：**另存为独立笔记**（默认，来源引用随副本保留）/ **以本地覆盖**（主进程先把外部
  版本另存为独立笔记再覆盖，双方内容都不丢）/ **载入磁盘版本**（显式确认后放弃本地草稿）；
- 未携带 `baseHash` 的旧调用保持后写覆盖（跨版本混跑不阻断，主进程不报错）；冲突未解决时，
  自动保存挂起，导航与关窗的冲刷会**阻止离开**（本地草稿留在编辑器，绝不静默丢弃）；
- 指纹是**本机判据**：防止的是「旧快照覆盖新写内容」，不承担跨设备互斥——跨设备仍靠单写者纪律
  ＋ 冲突副本检测（§9），不要把本机指纹当锁用。

### 4.5 全文索引派生文件（2026-10-09，WP-4）

`derived/` 内两个**可丢弃**文件，由 `src/main/metadata/fulltext.ts` 的 FulltextIndexer 维护
（识别队列只做 DOI/arXiv → 书目元数据，不再负责全文）：

- `derived/fulltext.txt`：PDF 文字提取结果，**全部可提取页**（上限 500 页 / 8MB，超限时 meta 标 `truncated`）；写出的是**原样文本**（不 trim）——`pageStarts` 的偏移以此为准。
- `derived/fulltext.meta.json`：`{ status: ready|empty|error, reason, engine, fileSha, pageCount, pages, chars, truncated, pageStarts, indexedAt }`。
  - `pageStarts`：每页起始字符偏移（升序）——阅读器「查找」按页统计与「命中跳转页码」都靠它；
  - 过期判定：引擎版本 / 绑定文件 sha / 页数任一不符，或上次 `error` → 启动或手动「重建」时重新入队；
  - 扫描版（无文本层）标 `empty` 并给出原因——**不伪装成已索引**；HTML 材料当前不建全文索引（标 `empty` + 原因）。
- 覆盖范围：所有导入路径（对话框 / arXiv 每日论文 / Zotero / 浏览器扩展 / 散装导入）都经 `importDocuments`，
  由 `Repo.onDocumentsImported` 回调统一入队——修复前只有「识别队列处理过的 needs-review 条目」才有全文，且只取前 5 页。
- 消费方：`librarySearch` 的自由词与 `全文:` 维度、`reader:find`（文档内查找）、文献库诊断横幅的覆盖统计
  （`hasFulltext` 由扫描时顺带判断，零额外 IO）。

## 5. 收件箱（收件箱/）

「先收集、后整理」的落点：界面上同一个入口（处理状态 待整理 / 已归档），磁盘上两类分开存。

### 5.0 照片

`<名>.<ext>`（原件图片）+ 同名 `.json` 侧车：`{schema:2, id, mediaType, byteSize, sha256, context, inboxStatus, spaceId, createdAt}`。删除成对删除。

### 5.1 速记（收件箱/速记/，2026-10-09）

零仪式的纯文本捕获：全局快捷键唤起，只写正文——不要标题、不选分区、不选学习区。一条速记一个文件：

`速记/<yyyyMMdd-HHmmss>-<id8>.md`，时间戳取自 `createdAt`（不可变 ⇒ 一 id 一文件、永不改名；外部改名后仍写回原处）。

```yaml
---
schema: 1
id: <uuid>
inboxStatus: inbox        # inbox（待整理）| filed（已归档）
spaceId: null             # 学习区归属，可为 null
todo: true                # 仅在为真时落键：以 `!` / 全角 `！` 开头捕获，或事后标记
createdAt: <iso>
```

## 9. 服务与索引契约

- `/api/asset/<sha256>?variant=original|display|thumb`：original 按索引解析绝对路径（条目文件 → 收件箱照片 → 笔记附件；Range 支持，PDF.js 必需）；display/thumb 到 `.cache/variants/` 生成（HEIC→JPEG 仍仅 macOS sips）。
- **内存索引**（MemoryIndex）：启动全扫 + `fs.watch` 递归监听（防抖 300ms 重扫）+ 5 分钟全扫兜底；iCloud 外部变更自动进索引并触发 `library:changed` 推送。
  - **增量扫描（2026-10-09，WP-6）**：扫描以「文件戳（mtime+size）」判定未变化，直接复用上次解析结果——未变的 entry.json / anchors.json / 笔记 / 速记 / 收件箱侧车**不读盘、不解析**；条目目录 mtime 未变时跳过冲突副本枚举（readdir）。3000 条实测：空转重扫 ~220ms 且 **0 次文件读**（此前全量 ~480ms / 6000 次读）。统计见 `FolderStore.lastScanStats`（durationMs / filesRead / filesStated）。
  - **冷启动仍是全量读**（首轮无缓存）；未实现「索引快照落盘」（`.cache/index.json`）与「按 watcher 路径定向重扫」——两者是后续可选项，当前规模下重启成本 ~0.5s/3000 条可接受。
  - 注意：防抖后的重扫是**全量遍历**（但未变文件零读盘），并非只重扫受影响子树。
- **冲突副本检测**：文件名含 `冲突`/`conflict`/`from other device` 的文件记入索引冲突清单，经 IPC 暴露给 UI（待整理区徽标），不自动处理。
- **库诊断（写入语义的另一半：失败必须可见）**：扫描产生的 malformed（坏文件/缺 entry.json）与 unfiled（分区目录里的散装文件）经只读 IPC `library:diagnostics` 暴露给界面——文献库横幅显示相对路径与处置方式（含 `.broken` 备份说明）。应用**不自动修改或搬移任何用户文件**；条目信息弹窗按 id 直取（`library:entryGet`），不再受检索返回上限影响。
- **保存成功语义**：`note:save` / `space:create|update` / `paper:feedCreate` 等用户可见写入一律「先写盘、成功后才提交内存索引」；方法 resolve 即代表已原子落盘，失败必须 reject（不留「重启就消失的幻影」）。主进程另有 `unhandledRejection` 日志兜底。
- 检索为扫描式：标题/作者/摘要/标签/笔记正文/速记正文/锚点 quote 内存子串匹配；PDF 全文检索按需读 `derived/fulltext.txt`。
- **全文读取是异步的**：主进程用 `fs/promises.readFile` 读全文并缓存到 Repo 实例（以 mtime+size 判有效性，外部同步覆盖后自动重读；上限 32MB 按 LRU 淘汰）。不阻塞事件循环——库在 iCloud 等网盘时也不会卡住整个应用。仅当检索词含自由词或显式 `全文:` 维度时才读全文；纯字段检索与首屏列表不读。
- **检索结果排序与上限**：默认按 `updatedAt` 倒序（同 `listNotes`），用户可在文献库切换为标题 / 第一作者 / 年份（新→旧，缺年份排最后）/ 最近导入（`createdAt`）——排序发生在截断**之前**。截取上限（`QUERY_LIMITS`）只截断传输量——`total` 是真实命中数，分面计数按「去掉该维度」统计，二者口径一致。
